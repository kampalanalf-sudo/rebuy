# GitHub Pages demo

The live site is a **static snapshot** of Rebuy: real code, real data, no server.

* Shop app — `index.html` → `https://<user>.github.io/rebuy/`
* Platform admin — `admin.html` → `https://<user>.github.io/rebuy/admin.html`

## How it works

GitHub Pages serves files only, so there is no Python process. Two pieces bridge
that gap:

| File | What it does |
|---|---|
| `docs/demo.json` | one real shop's customers, sales, line items, reminders, messages, coupons, templates |
| `docs/demo-api.js` | answers `/api/*` in the browser from `demo.json`; also contains a JS port of `app/engine.py` (cycle maths, rendering, risk bands) |
| `docs/admin.json` | every admin endpoint's real JSON output, generated by calling the handler functions |
| `docs/admin-api.js` | answers `/api/admin/*` from `admin.json` |

Both shims refuse writes with an explicit "read-only demo" message rather than
pretending a save worked.

`/api/auth/me` reports `google_enabled: false` and `signup_open: false` in the
snapshot, so the sign-in screen shows "single sign-on is not enabled on this
deployment" instead of a Google button that cannot possibly work. Everything
account-related (passwords, sessions, invitations) is stubbed read-only; the
real flows live in the Python app.

## Rebuild

```bash
# shop app: picks a shop from data/rebuy.db
python3 scripts/build_pages.py --shop 1

# admin cockpit: calls the real handlers, snapshots their output
python3 scripts/build_admin_pages.py
```

Run them in that order (the shop build keeps existing admin files; the admin
build needs the schema initialised, which `build_pages.py` does).

## Publish

```bash
git add docs && git commit -m "Refresh Pages demo" && git push
```

Then in the repo: **Settings → Pages → Build and deployment → Source: Deploy
from a branch → Branch: `main`, folder `/docs`**.

`docs/.nojekyll` is included so files starting with `_` are served as-is.

## What is live vs. not

| Works | Disabled |
|---|---|
| Dashboard, customers, customer 360, reminders, inbox, reports, products, sales, loyalty, coupons, segments, team list, profile | Recording a sale, sending a message, importing a file, inviting a team member, editing a password |
| Admin overview, shops, shop detail, messaging, retention, revenue, queue, capacity, providers, audit log | Pausing a shop, editing credentials, reseeding, running the worker |

For the full app with a live database, run `python3 serve.py` (SQLite) or point
`REBUY_DATABASE_URL` at the Supabase project — see `deploy/supabase.md`.
